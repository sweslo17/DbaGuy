# 03b: SQL Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SQL Server 2016+ (SQL logins) a first-class DbaGuy engine: connect incl. SSH and TLS, server → database → schema tree, DDL, table data, `GO` batches with `GO n`, streaming with multiple result sets, live `PRINT` / `RAISERROR … WITH NOWAIT`, cancel without wedging the session, timeout, manual commit, and application-level read-only with the limit stated in the UI.

**Architecture:** `sql/` gains `Dialect.TSQL` only through its rule tables: bracket and `N''` lexing, `GO` lines as batch separators (`StatementSpan.repeat` carries `GO n`), and a lexical T-SQL statement cutter (`sql/tsql.py`) so a batch is classified statement by statement even without `;`. The adapter contract gains one default method, `set_message_listener`, which the worker sets per request. A new `adapters/mssql/` package (settings + freetds.conf, catalog/introspection/schema, types, adapter) implements the unchanged contract on pymssql's low-level `_mssql` API: verbatim batches, a phase lock that sends the cancel across threads only while the worker waits for the server, `SET IMPLICIT_TRANSACTIONS` for manual commit with a cached `@@TRANCOUNT` state, and first-result-set column types from `sys.dm_exec_describe_first_result_set`. The frontend reads `repeat` and `server_read_only`; nothing else is engine-specific.

**Tech Stack:** Python 3.13, FastAPI, pydantic v2, loguru, sqlglot 30.23 (`TSQL` dialect imported by name), pymssql 2.4.4 (bundled FreeTDS 1.5.19 + OpenSSL 3), SQL Server 2022 in Docker (OrbStack, amd64 under Rosetta); React 19 + TypeScript, `@codemirror/lang-sql` 6.10.0 (`MSSQL`), `sql-formatter` 15.9.0 (`"transactsql"`).

**Spec:** docs/superpowers/specs/2026-10-17-03-mysql-mssql-design.md (§5 item 2)

## Review Focus

1. **Every statement of a T-SQL batch is judged, with or without `;`.** T-SQL needs no terminator, and sqlglot parses `DECLARE @x INT\nDELETE FROM t` as one `Command`, so without Task 3's cuts that batch would be READ. `SELECT 1\nDROP TABLE t` must be DDL + `drop`, `DECLARE @x int = 1; SELECT @x` READ (allowed read-only), `EXEC p` UNKNOWN (blocked read-only), and a table-data filter `id = 1 DELETE FROM t` rejected. → Task 3 `test_tsql`, `test_tsql_read_only_*`, `test_a_tsql_filter_cannot_append_a_statement`.
2. **No cross-thread cancel while rows stream, and no stray cancel.** `MSSQLConnection.cancel()` crosses threads only in the EXECUTING phase (waiting for the server); while streaming only a flag is set and the worker thread cancels before its next row; an idle cancel does nothing; the flag belongs to one statement, so a later error is never relabelled "cancelled". → Task 8 `test_cancel_while_waiting_for_the_server`, `test_cancel_mid_stream_then_reuse`, `test_cancel_with_nothing_running_is_harmless`, `test_a_cancel_never_relabels_later_errors`.
3. **`GO` splits exactly where sqlcmd splits.** `GO`, `go 3 -- c`, CRLF; not `GO;`, `GO2`, `GO /*c*/`, nor GO inside strings, comments (nested) or `[names]`; `GO 0` runs nothing; `repeat` reaches the run loop; offsets stay UTF-16-correct with CJK and emoji. → Task 2 splitter tests, Task 9 manual check.
4. **Transaction state never costs a query while a result is open, and DbaGuy's own queries never change the user's transaction.** Manual mode is `SET IMPLICIT_TRANSACTIONS ON`; Commit commits every nesting level; the describe query never opens an implicit transaction and never aborts an `XACT_ABORT ON` transaction (the DMF, not `sp_describe_first_result_set`). → Task 8 `test_manual_commit_mode_uses_implicit_transactions`, `test_dbaguys_own_queries_never_abort_the_users_transaction`, `test_a_paused_result_in_manual_mode_reports_a_transaction`.
5. **Messages and errors are what SQL Server said.** `PRINT` / `RAISERROR … WITH NOWAIT` arrive live and in order; errors carry the number as the code and the batch line as the position (no position inside a procedure); pymssql's sticky process-wide login-error state never shows a stale reason; a dead connection is `connection_lost`. → Task 8 `test_messages_arrive_live_and_in_order`, `test_errors_carry_number_and_line`, `test_wrong_password_twice`, `test_a_killed_connection_is_reported_as_lost`.

```python
_GO_REST = re.compile(r"(?:[ \t]+(\d+))?[ \t]*(?:--[^\r\n]*)?\r?(?=\n|\Z)")  # after GO: [count] [-- comment], line end
_MODULES = frozenset({"PROC", "PROCEDURE", "FUNCTION", "TRIGGER", "VIEW"})


def _go_line(text: str, token: Token) -> re.Match[str] | None:
    """A T-SQL `GO [n]` line, as sqlcmd and SSMS read it: the word GO alone on its line, optionally followed by a count
    and a `--` comment. `GO;`, `GO2` and `GO /* c */` are not. A GO inside a string, comment or [name] is not a WORD
    token, so it never gets here. Linear: only the spaces and tabs before the word are looked at."""
    if token.kind != TokenKind.WORD or token.upper != "GO":
        return None
    i = token.start
    while i > 0 and text[i - 1] in " \t":
        i -= 1
    if i > 0 and text[i - 1] != "\n":
        return None
    return _GO_REST.match(text, token.end)


def _defines_module(significant: list[Token]) -> bool:
    """CREATE [OR ALTER] | ALTER  PROC|PROCEDURE|FUNCTION|TRIGGER|VIEW. T-SQL requires such a statement to be the only
    one in its batch, so everything after it, up to the GO line, is the module's body and runs later, not now."""
    words = [t.upper if t.kind == TokenKind.WORD else "" for t in significant[:4]]
    if words[:3] == ["CREATE", "OR", "ALTER"]:
        return words[3:4] != [] and words[3] in _MODULES
    return words[:1] in (["CREATE"], ["ALTER"]) and len(words) > 1 and words[1] in _MODULES


def _split_batches(text: str, dialect: Dialect) -> list[StatementSpan]:
    """T-SQL: batches end at GO lines (spec §3.3); `;` never splits a batch, because variables and temporary tables
    live as long as the batch."""
    spans: list[StatementSpan] = []
    start = 0
    while True:
        current: list[Token] = []
        line: re.Match[str] | None = None
        for token in scan(text, dialect, start):
            if line := _go_line(text, token):
                break
            current.append(token)
        significant = [t for t in current if t.kind not in INSIGNIFICANT]
        if line is None:
            _emit(spans, text, current, None, _defines_module(significant))
            return spans
        _emit(spans, text, current, line.end(), _defines_module(significant), int(line.group(1) or 1))
        start = line.end()
```

```python
"""Statements inside a T-SQL batch. T-SQL needs no `;` between statements, so a batch is cut before every word that
starts a statement, unless that word continues the statement before it (GRANT SELECT, INSERT…; UPDATE t SET …;
ON DELETE SET NULL; UNION SELECT; OFFSET … FETCH; CASE … ELSE … END; …). The classifier judges every piece and keeps
the strictest result, so a wrong cut can only make a batch stricter, never let a write pass as a read (spec §3.4).
Pure; never raises."""

from .lexer import Token, TokenKind

STATEMENT_STARTS = frozenset("""SELECT INSERT UPDATE DELETE MERGE DECLARE SET IF ELSE WHILE BEGIN END PRINT RAISERROR
    THROW EXEC EXECUTE WAITFOR RETURN BREAK CONTINUE GOTO CREATE ALTER DROP TRUNCATE USE GRANT REVOKE DENY BACKUP
    RESTORE DBCC KILL BULK COMMIT ROLLBACK SAVE OPEN FETCH CLOSE DEALLOCATE CHECKPOINT RECONFIGURE SHUTDOWN SETUSER
    REVERT""".split())
# A start word right after one of these words continues the statement.
_CONTINUES_AFTER: dict[str, frozenset[str]] = {
    "SELECT": frozenset({"UNION", "ALL", "EXCEPT", "INTERSECT", "FOR"}),  # set operators; DECLARE … CURSOR FOR SELECT
    "INSERT": frozenset({"THEN", "ON", "FOR", "AFTER", "OF", "BULK"}),  # MERGE actions, ON DELETE|UPDATE, cursors, BULK INSERT
    "UPDATE": frozenset({"THEN", "ON", "FOR", "AFTER", "OF"}),
    "DELETE": frozenset({"THEN", "ON", "FOR", "AFTER", "OF"}),
    "MERGE": frozenset({"INNER", "OUTER", "LEFT", "RIGHT", "FULL", "CROSS"}),  # INNER MERGE JOIN (a join hint)
    "SET": frozenset({"UPDATE", "DELETE"}),  # ON DELETE SET NULL, MERGE … UPDATE SET
    "FETCH": frozenset({"ROW", "ROWS"}),  # OFFSET n ROWS FETCH NEXT …
}
# In a statement that begins with the key, the first of these words (at parenthesis depth 0) continues it.
_CONTINUES_ONCE_IN: dict[str, frozenset[str]] = {
    "WITH": frozenset({"SELECT", "INSERT", "UPDATE", "DELETE", "MERGE"}),  # the CTE's statement
    "UPDATE": frozenset({"SET"}),
    "INSERT": frozenset({"SELECT", "EXEC", "EXECUTE"}),  # INSERT … SELECT, INSERT … EXEC
    "ALTER": frozenset({"ALTER", "DROP", "SET"}),  # ALTER TABLE t ALTER COLUMN | DROP COLUMN, ALTER DATABASE x SET
}
# Statements that only `;` ends: T-SQL requires MERGE to end with one; privilege lists name statement words.
_UNTIL_SEMICOLON = frozenset({"MERGE", "GRANT", "REVOKE", "DENY"})


def _word(token: Token) -> str:
    return token.upper if token.kind == TokenKind.WORD else ""


def _continues(current: list[Token], seen: set[str], word: str, tokens: list[Token], i: int) -> bool:
    previous = current[-1]
    if previous.kind == TokenKind.COMMA:
        return True  # a comma never ends a statement
    head = _word(current[0])
    if head in _UNTIL_SEMICOLON or _word(previous) in _CONTINUES_AFTER.get(word, ()):
        return True
    group = _CONTINUES_ONCE_IN.get(head, frozenset())
    if word in group and not group & seen:
        return True
    # DROP TABLE IF EXISTS t: an IF that is followed by EXISTS and a name, not by EXISTS (subquery)
    return (
        word == "IF" and i + 2 < len(tokens) and _word(tokens[i + 1]) == "EXISTS"
        and tokens[i + 2].kind != TokenKind.LPAREN
    )


def statements(tokens: list[Token]) -> list[list[Token]]:
    """`tokens`: the significant tokens of one batch. Cut at `;` and before a statement start at parenthesis depth 0
    outside CASE … END."""
    out: list[list[Token]] = []
    current: list[Token] = []
    seen: set[str] = set()  # words at depth 0 in `current`, its first word excepted
    depth = cases = 0
    for i, token in enumerate(tokens):
        if token.kind == TokenKind.SEMI and depth == 0:
            if current:
                out.append(current)
            current, seen = [], set()
            continue
        word = _word(token)
        if current and depth == 0 and cases == 0 and word in STATEMENT_STARTS and not _continues(current, seen, word, tokens, i):
            out.append(current)
            current, seen = [], set()
        current.append(token)
        if token.kind == TokenKind.LPAREN:
            depth += 1
        elif token.kind == TokenKind.RPAREN:
            depth = max(depth - 1, 0)
        elif word == "CASE":
            cases += 1
        elif word == "END" and cases:
            cases -= 1
        if depth == 0 and word and len(current) > 1:
            seen.add(word)
    if current:
        out.append(current)
    return out
```

```python
_DIALECT_KEYWORD_KIND[Dialect.TSQL] = {  # spec §3.4

_TSQL_CONTROL = frozenset({"IF", "ELSE", "WHILE", "BREAK", "CONTINUE", "GOTO", "RETURN", "END"})
_TSQL_BEGIN_TRANSACTION = frozenset({"TRAN", "TRANSACTION", "DISTRIBUTED"})

# no write can pass as something milder. Kinds only; the dangerous reasons come from the statements.
_TSQL_FLOOR: dict[str, StatementKind] = {
    **dict.fromkeys(("INSERT", "UPDATE", "DELETE", "MERGE", "BULK", "UPDLOCK", "XLOCK"), StatementKind.WRITE),
    **dict.fromkeys(("CREATE", "ALTER", "DROP", "TRUNCATE", "GRANT", "REVOKE", "DENY"), StatementKind.DDL),
    **dict.fromkeys(
        ("EXEC", "EXECUTE", "DBCC", "BACKUP", "RESTORE", "KILL", "SHUTDOWN", "RECONFIGURE", "CHECKPOINT", "OPENROWSET",
         "OPENQUERY", "OPENDATASOURCE", "SETUSER"),
        StatementKind.UNKNOWN,
    ),
}


def _tsql_rule(words: list[str]) -> Classification | None:
    """T-SQL statements decided before sqlglot (spec §3.4); None when the general rules decide."""
    first = words[0] if words else ""
    if first in _TSQL_CONTROL or (first == "BEGIN" and words[1:2] not in [[w] for w in _TSQL_BEGIN_TRANSACTION]):
        return Classification(kind=StatementKind.READ)  # IF, ELSE, WHILE, BEGIN … END, BEGIN TRY, END CATCH, …
    if first == "SET" and len(words) > 1 and words[1].startswith("@") and not words[1].startswith("@@"):
        return Classification(kind=StatementKind.READ)  # SET @var = …: a variable, not a session setting
    if words[:2] == ["UPDATE", "STATISTICS"]:
        return Classification(kind=StatementKind.WRITE)  # maintenance; it has no WHERE to miss
    return None


def _classify_tsql_batch(sql: str, has_body: bool) -> Classification:
    """A T-SQL batch (the text between GO lines): every statement judged, with or without `;` between them, the
    strictest wins, and no word of the batch may be stricter than that (the floor). A batch that defines a procedure,
    function, trigger or view is that one DDL statement: its body runs later, not now."""
    if has_body:
        return _classify_single(sql, Dialect.TSQL, has_body=True)
    tokens = [t for t in tokenize(sql, Dialect.TSQL) if t.kind not in INSIGNIFICANT]
    results = [_classify_single(sql[p[0].start:p[-1].end], Dialect.TSQL) for p in statements(tokens)]
    combined = _combine(results) if results else Classification(kind=StatementKind.UNKNOWN)
    floor = max(
        (_TSQL_FLOOR.get(t.upper, StatementKind.READ) for t in tokens if t.kind == TokenKind.WORD),
        key=_SEVERITY.index, default=StatementKind.READ,
    )
    if _SEVERITY.index(floor) > _SEVERITY.index(combined.kind):
        return Classification(kind=floor, dangerous_reasons=combined.dangerous_reasons)
    return combined
```

```python
    def _listen(self, request_id: str | None) -> None:
        """Route messages the connection delivers as they arrive to `request_id`'s Messages (None: stop). Connections
        without live messages ignore it and keep using take_messages()."""
```

```bash
#!/bin/bash
# Seeds the dev SQL Server (the mssql-init one-shot container): waits for the server, skips when the seed already ran,
# then runs init/*.sql in order. -I: QUOTED_IDENTIFIER ON (filtered indexes need it); -b: stop at the first error.
set -euo pipefail
SQLCMD=(/opt/mssql-tools18/bin/sqlcmd -S mssql -U sa -P "$MSSQL_SA_PASSWORD" -C -I -b)
for _ in $(seq 1 120); do
  if "${SQLCMD[@]}" -Q "SELECT 1" >/dev/null 2>&1; then break; fi
  sleep 2
done
seeded="$("${SQLCMD[@]}" -h -1 -W -Q "SET NOCOUNT ON; SELECT CASE WHEN OBJECT_ID('dbaguy.dbo.seed_done') IS NULL THEN 0 ELSE 1 END")"
if [[ "$seeded" == "1" ]]; then
  echo "already seeded"
  exit 0
fi
for file in /mssql/init/[0-9]*.sql; do
  echo "seeding $file"
  "${SQLCMD[@]}" -i "$file"
done
```

Facts behind the TLS mapping (probed while planning with pymssql 2.4.4 / FreeTDS 1.5.19 against SQL Server 2022):
- pymssql's `encryption` accepts only `default`, `off`, `request`, `require`. No parameter names a CA file or a host name check, and there is no `strict`. The CA and the host check therefore go through a `freetds.conf` section, and `strict` (TDS 8.0) is not supported (it also failed against the dev server).
- With `request`, the dev server reported `encrypt_option FALSE`: only the login is encrypted unless the server forces encryption. With `require` it reported `TRUE`.
- A section works with pymssql when `server` is the section's name and `port` is the section's port. FreeTDS re-reads `FREETDSCONF` at every login, so the file may change between logins.
- `ca file` set to a CA that did not sign the server's certificate fails the login (as does `ca file = system` against the self-signed dev server). Without `ca file`, `require` does not verify at all. FreeTDS's bundled OpenSSL does not read the macOS keychain, so verify-ca and verify-full need a CA file.

Mapping (spec §3.6): `disable` → `off`; `prefer` → `request`; `require` → `require`; `verify-ca` → `require` + section (`ca file`, `check certificate hostname = no`); `verify-full` → `require` + section (`check certificate hostname = yes`). Through an SSH tunnel, `verify-full` fails before connecting (it would check 127.0.0.1); `verify-ca` connects to the tunnel's local end with the CA check only.

```python
_HEADER = (
    "# Written by DbaGuy: FreeTDS reads it at every SQL Server login. Edits are overwritten.\n"
    "[global]\n\ttds version = 7.4\n"
)


@dataclass(frozen=True)
class TdsSection:
    host: str
    port: int
    ca_file: str  # expanded path
    check_hostname: bool  # verify-full; verify-ca checks the CA only

    @property
    def name(self) -> str:
        digest = hashlib.sha256(f"{self.host}\0{self.port}\0{self.ca_file}\0{self.check_hostname}".encode()).hexdigest()
        return f"dbaguy_{digest[:16]}"


class FreeTdsConfig:
    def __init__(self, path: Path) -> None:
        self.path = path
        self._lock = threading.Lock()
        self._sections: dict[str, TdsSection] = {}

    def render(self) -> str:
        parts = [_HEADER]
        for name, s in self._sections.items():
            parts.append(
                f"\n[{name}]\n\thost = {s.host}\n\tport = {s.port}\n\ttds version = 7.4\n\tencryption = require\n"
                f"\tca file = {s.ca_file}\n\tcheck certificate hostname = {'yes' if s.check_hostname else 'no'}\n"
            )
        return "".join(parts)

    def write(self) -> None:
        self.path.parent.mkdir(parents=True, exist_ok=True)
        with atomic_text_file(self.path) as fp:
            fp.write(self.render())

    def section_for(self, target: TdsSection) -> str:
        """The section's name; the file is rewritten (atomically) when the section is new."""
        if any(c in value for value in (target.host, target.ca_file) for c in "\r\n"):
            raise ConnectionFailed("The host name or CA file path holds a line break, which freetds.conf cannot carry")
        if not os.path.isfile(target.ca_file):
            raise ConnectionFailed(f"CA file not found: {target.ca_file}")
        with self._lock:
            if target.name not in self._sections:
                self._sections[target.name] = target
                self.write()
                logger.debug("freetds.conf section {} for {}:{}", target.name, target.host, target.port)
        return target.name
```

  The functions follow these rules:
  - **`connect_params`:**
    - A host containing `\` raises `ConnectionFailed(_NAMED_INSTANCE)`.
    - `kwargs` exactly as in the test: `server` = `endpoint.host`, `port` = `str(endpoint.port)`, `user` = `profile.username or ""`, `password` = `password or ""`, `database` = `database or profile.database or ""`, `appname="DbaGuy"`, `charset="UTF-8"`, `tds_version`, `encryption` from `_ENCRYPTION`, `conn_properties=SESSION_DEFAULTS`.
    - Options are an allow-list (Ruling 24): only `tds_version` (key case-insensitive); a value outside `_TDS_VERSIONS` raises `ConnectionFailed(f"tds_version must be one of 7.0-7.4, not {value!r}")`. Every other key is ignored and logged at WARNING by name only.
    - `cert_file` / `key_file` set: WARNING `"SQL Server does not use client certificates; ignoring them for profile {}"`.
    - `verify-ca` / `verify-full` → `tds_section`:
      - `verify-full` with `endpoint.tls_server_name` → `ConnectionFailed("verify-full checks the server's host name, which FreeTDS cannot do through an SSH tunnel (it would check 127.0.0.1); use verify-ca, or connect without the tunnel")`;
      - no `ca_file` → `ConnectionFailed(f"SSL mode {mode} needs a CA file for SQL Server: FreeTDS does not read the macOS keychain")`;
      - otherwise `TdsSection(endpoint.host, endpoint.port, os.path.expanduser(ca_file), mode == "verify-full")`.
  - **`parse_mssql_url(url)`:**
    - Split off the scheme at `://`. If the part before any `?` holds a `;`, parse the JDBC form; otherwise the URL form.
    - **JDBC form** `host[:port][;key=value]…`:
      - A property without `=` raises `ValidationFailed("A JDBC SQL Server URL takes key=value properties after the host")`.
      - Keys are folded (`lower()`, `-` and `_` removed).
      - The host comes from the address or `serverName`; the port from the address or `portNumber`.
      - `databaseName`/`database`, `user`/`userName`, `password`, `encrypt`, `trustServerCertificate` are read.
      - `integratedSecurity=true`, or an `authentication` other than `SqlPassword`, raises `ValidationFailed("Windows and Azure AD logins are not supported: use a SQL login")`.
      - Other keys are dropped with a WARNING (names only).
    - **URL form** (`urlparse`):
      - User name and password are `unquote`d.
      - The database is the path, or the query `database`.
      - The query keys `user`, `password`, `encrypt`/`encryption`, `trustservercertificate` and `tdsversion` (kept as option `tds_version`) are read; others are dropped with a WARNING.
      - The host is `unquote`d before the checks below, so `%5C` counts as a backslash.
    - Both forms:
      - A `\` in the host raises `ValidationFailed(_NAMED_INSTANCE)`.
      - A port that is not a number raises `ValidationFailed("Invalid port in the SQL Server URL")`.
      - No host raises `ValidationFailed(f"A SQL Server URL needs a host, {_URL_HINT}")`.
      - The name is `f"{host}/{database}"` or `host`.
    - `encrypt` (case-insensitive):
      - `disable` → `disable`;
      - `false`/`no`/`optional` → `prefer`;
      - `true`/`yes`/`mandatory` → `require` when `trustServerCertificate` is `true`/`yes`, else `verify-full`;
      - `strict` → `ValidationFailed("encrypt=strict (TDS 8.0) is not supported; use encrypt=true")`;
      - anything else → `ValidationFailed(f"Unknown encrypt value '{value}' in the SQL Server URL")`;
      - absent → the `SslConfig` default.
    - Return `ParsedUrl(ServerProfileDraft(engine="mssql", …), password)`.

Tree shape (spec §3.6):
- `[]` → databases the login may open (`HAS_DBACCESS`, online), kind `database`, `has_children=True`, `system` for `SYSTEM_DATABASES`, user databases first, each group by name.
- `[db]` → every schema, kind `schema`, `has_children=True`, `system` per `is_system_schema`, user schemas first, by name.
- `[db, schema]` → the non-empty folders in the order `tables, views, functions, procedures, sequences, synonyms, types` (one `UNION ALL` count query). The schema must exist (`NotFound(f"Schema '{name}' not found")`).
- `[db, schema, folder]` → objects:

  | Folder | Kind | Children | Detail |
  |---|---|---|---|
  | tables | `table` | yes | — |
  | views | `view` | yes | — |
  | functions | `function` | no | `scalar` / `inline table` / `table` |
  | procedures | `procedure` | no | — |
  | sequences | `sequence` | no | its type, e.g. `bigint` |
  | synonyms | `synonym` | no | the base object, e.g. `[dbo].[customers]` |
  | types | `type` | no | `table type`, or the base type, e.g. `nvarchar(200)` |

- `[db, schema, tables|views, rel]` → `columns`; a table also `indexes`, `foreign_keys`, `triggers` when non-empty (one count query; indexes counted are rowstore types 1 and 2).
- `[…, rel, folder]` leaves: `column` (detail `type [NOT NULL] [PK]`), `index` (`primary` / `unique` / none; primary first, then by name), `foreign_key` (`(a, b) → schema.table (x, y)`), `trigger` (`after insert`, `instead of insert, update`; events joined in Python: `STRING_AGG` needs SQL Server 2017 and the target is 2016+).
- `path[0]` must be kind `database`, `path[1]` kind `schema`; an unknown folder raises `ValidationFailed`. Names are interpolated only through `literal()` / `q()` / `object_id_sql()`.

`object_detail`:

| Kind | DDL | `ddl_is_generated` | Also |
|---|---|---|---|
| table | generated (below) | True | `columns`, `comment` (MS_Description) |
| view | `OBJECT_DEFINITION` | False | `columns` |
| procedure, function, trigger | `OBJECT_DEFINITION` (a trigger's schema is its table's) | False | — |
| sequence, synonym, type | generated | True | — |
| index, foreign_key | generated from the table at `path[3]` | True | — |
| column | none | — | `columns=[that ColumnInfo]` |

A NULL definition (encrypted module, or no VIEW DEFINITION permission) gives `ddl=None`. A missing object (`OBJECT_ID` / `TYPE_ID` NULL, or a missing index or key) raises `NotFound(f"{kind} '{name}' not found")`. Any other kind raises `ValidationFailed(f"No details available for {kind}")`.

Catalog facts (probed as the `dbaguy` login while planning): `sys.sequences`' values and `sys.identity_columns`' seed and increment are `sql_variant`, which pymssql returns as raw bytes, so the queries `CAST(… AS nvarchar(40))` them. `HAS_DBACCESS` lists master, msdb and tempdb (guest access) and hides model and `locked_away`. A user's default schema is `dbo`.

```python
_CHARS = frozenset({"char", "varchar", "binary", "varbinary"})
_NCHARS = frozenset({"nchar", "nvarchar"})  # max_length counts bytes: two per character
_SCALED = frozenset({"decimal", "numeric"})
_FRACTION = frozenset({"datetime2", "datetimeoffset", "time"})


def type_sql(type_name: str, max_length: int, precision: int, scale: int) -> str:
    """A column's type as T-SQL writes it, from sys.types / sys.columns. An alias type (`email_address`) keeps its
    name: its length and precision are the alias's."""
    if type_name in _NCHARS:
        return f"{type_name}({'max' if max_length == -1 else max_length // 2})"
    if type_name in _CHARS:
        return f"{type_name}({'max' if max_length == -1 else max_length})"
    if type_name in _SCALED:
        return f"{type_name}({precision},{scale})"
    if type_name in _FRACTION:
        return f"{type_name}({scale})"
    if type_name == "float" and precision != 53:
        return f"float({precision})"
    return type_name
```

```python
_ACTIONS = {"NO_ACTION": "NO ACTION", "CASCADE": "CASCADE", "SET_NULL": "SET NULL", "SET_DEFAULT": "SET DEFAULT"}


def _column_line(c: _Column, named: bool) -> str:
    if c.computed is not None:
        return f"{q(c.name)} AS {c.computed}{' PERSISTED' if c.persisted else ''}"
    type_text = f"{q(c.user_schema)}.{q(c.type_name)}" if c.user_schema else type_sql(c.type_name, c.max_length, c.precision, c.scale)
    parts = [q(c.name), type_text]
    if c.collation and c.collation != c.database_collation:
        parts.append(f"COLLATE {c.collation}")
    if c.identity:
        parts.append(f"IDENTITY({c.seed}, {c.increment})")
    parts.append("NULL" if c.nullable else "NOT NULL")
    if c.default is not None:
        parts.append(f"CONSTRAINT {q(c.default_name)} DEFAULT {c.default}" if named else f"DEFAULT {c.default}")
    return " ".join(parts)


def _foreign_key_clause(name: str, parts: list[tuple]) -> str:
    """parts: _FOREIGN_KEYS rows of one key, in key order."""
    _, _, ref_schema, ref_table, _, on_delete, on_update = parts[0]
    columns = ", ".join(q(p[1]) for p in parts)
    ref_columns = ", ".join(q(p[4]) for p in parts)
    return (f"CONSTRAINT {q(name)} FOREIGN KEY ({columns}) REFERENCES {q(ref_schema)}.{q(ref_table)} ({ref_columns}) "
            f"ON DELETE {_ACTIONS[on_delete]} ON UPDATE {_ACTIONS[on_update]}")


def _index_statement(schema: str, table: str, name: str, parts: list[tuple]) -> str:
    """parts: _INDEXES rows of one index. A primary key or unique constraint becomes ALTER TABLE … ADD CONSTRAINT."""
    keys = ", ".join(q(p[4]) + (" DESC" if p[5] else "") for p in parts if not p[6])
    target = f"{q(schema)}.{q(table)}"
    is_unique, type_desc, filter_definition, is_primary, is_constraint = parts[0][1], parts[0][2], parts[0][3], parts[0][7], parts[0][8]
    if is_primary or is_constraint:
        return f"ALTER TABLE {target} ADD CONSTRAINT {q(name)} {'PRIMARY KEY' if is_primary else 'UNIQUE'} {type_desc} ({keys});"
    included = [q(p[4]) for p in parts if p[6]]
    sql = f"CREATE {'UNIQUE ' if is_unique else ''}{type_desc} INDEX {q(name)} ON {target} ({keys})"
    if included:
        sql += f" INCLUDE ({', '.join(included)})"
    if filter_definition:
        sql += f" WHERE {filter_definition}"
    return sql + ";"


def _body_lines(conn: Connection, object_sql: str, named: bool) -> list[str]:
    """Columns, then PRIMARY KEY / UNIQUE, then CHECK constraints. `named`: a table names its constraints; a table type
    may not."""
    lines = [_column_line(c, named) for c in _columns(conn, object_sql)]
    for name, parts in _grouped(rows(conn, _KEYS.format(o=object_sql))).items():
        kind = "PRIMARY KEY" if parts[0][1] else "UNIQUE"
        columns = ", ".join(q(p[3]) + (" DESC" if p[4] else "") for p in parts)
        lines.append(f"{f'CONSTRAINT {q(name)} ' if named else ''}{kind} {parts[0][2]} ({columns})")
    for name, definition in rows(conn, _CHECKS.format(o=object_sql)):
        lines.append(f"{f'CONSTRAINT {q(name)} ' if named else ''}CHECK {definition}")
    return lines


def _table_ddl(conn: Connection, schema: str, table: str) -> str:
    o = object_id_sql(schema, table)
    lines = _body_lines(conn, o, named=True)
    lines += [_foreign_key_clause(name, parts) for name, parts in _grouped(rows(conn, _FOREIGN_KEYS.format(o=o))).items()]
    statements = ["CREATE TABLE {} (\n    {}\n);".format(f"{q(schema)}.{q(table)}", ",\n    ".join(lines))]
    for name, parts in _grouped(rows(conn, _INDEXES.format(o=o))).items():
        if not (parts[0][7] or parts[0][8]):  # constraint indexes are already in the body
            statements.append(_index_statement(schema, table, name, parts))
    return "\n".join(statements)
```

  - The table-type DDL is `"CREATE TYPE {} AS TABLE (\n    {}\n);"` over `_body_lines(conn, _TABLE_TYPE_OBJECT.format(ref=…), named=False)`.
  - An alias type is `CREATE TYPE [s].[n] FROM <type_sql of the base type> [NOT ]NULL;`.
  - A sequence is `CREATE SEQUENCE [s].[n] AS <type> START WITH … INCREMENT BY … MINVALUE … MAXVALUE … [NO ]CYCLE <CACHE [n] | NO CACHE>;` (`is_cached` with a NULL `cache_size` is plain `CACHE`).

  - `ColumnInfo` comes from `_Column`: `type_name` is the alias name or `type_sql(…)`; `nullable`, `default`, `is_primary_key`, `comment`.

Facts the code relies on (probed while planning, pymssql 2.4.4 / FreeTDS 1.5.19 / SQL Server 2022; the spec's probe added the first two):
- **Cancel.** `MSSQLConnection.cancel()` from another thread while the worker waits inside `execute_query` (e.g. `WAITFOR DELAY`) ends the statement in about 1.05 s with `MSSQLDatabaseException` number 0 "Unknown error"; the next statement works. The same call on the worker thread between rows takes 4 ms; afterwards `#temp` tables and `@@TRANCOUNT` (also in implicit-transaction mode) are intact. An idle cross-thread cancel is harmless. A cross-thread cancel that lands while a *later* statement runs cancels that statement, which is why the flag must belong to one statement. Cancelling inside `set_wait_callback` wedged the session (spec probe), and the research saw cross-thread cancel hang while streaming.
- **Server buffering.** SQL Server holds a result's last partial packet until the batch moves on. `SELECT 1; WAITFOR DELAY '00:00:06'; SELECT 2` blocks inside `execute_query` for the 6 s (EXECUTING: cancellable). After a 5,000-row set, reading its last rows blocks until a following `WAITFOR` ends (STREAMING: the cancel waits for those rows; documented limit).
- **Result sets.** pymssql skips result sets without columns, so a batch reports one row count, the last statement's; `rows_affected` is -1 when that statement had none. `nextresult()` drains the rest of the current set before moving on. `get_header()` gives `(name, code, …)`; the codes are unreliable (date, datetime and UUID all report 2).
- **Messages.** `set_msghandler(handler)` is called with `(msgstate, severity, srvname, procname, line, msgtext)`, the strings as bytes, for every message including errors, on the thread inside the driver call. `PRINT` without NOWAIT is buffered by the server until a NOWAIT, the batch end or a full packet. Severity 10 arrives as 0.
- **Errors.** With `min_error_severity = 11`, server errors raise `MSSQLDatabaseException` with `number`, `severity`, `line` (1-based in the batch), `procname` and `text` (bytes; the server text followed by `DB-Lib error message 20018, severity N:…`). An error after the first result set is raised by `nextresult()`; pymssql then cancels the rest of the batch's *results*, but the server still runs the rest of the batch (probed: later INSERTs landed). A killed session raises number 0 "Unknown error" on every call, and `connected` stays True (DB-Lib's own errors are below severity 11, so their text never arrives).
- **Login errors.** pymssql keeps login-error state in process globals and never clears the number or severity. After one failed login, later failures report number 18456 with no server text, and a refused port reports "18456 Unknown error". Only a server sentence such as `Login failed for user 'x'.` can be trusted, and only when present.
- **Transactions.** With `SET IMPLICIT_TRANSACTIONS ON`, `SELECT 1` opens no transaction, but a SELECT from a table (`sys.objects` included) does. `SELECT * FROM sys.dm_exec_describe_first_result_set(…)` opens one too; `EXEC sp_describe_first_result_set` does not. Nested `BEGIN TRAN` made `@@TRANCOUNT` 3, and `IF @@TRANCOUNT > 0 COMMIT` left 2. Under `SET XACT_ABORT ON` inside an open transaction, an error from `EXEC sp_describe_first_result_set` rolled the transaction back, while the DMF returned error rows (11525 for temp tables created in the batch, 208, 2812) and left it open. `XACT_STATE()` reported 1 with `@@TRANCOUNT` 0 after implicit mode had been used, so it never decides `in_transaction`. A doomed transaction is rolled back at the batch end (3998), so `XACT_STATE() = -1` is rarely seen between batches.
- **Types.** decimal → `Decimal` (`Decimal('0E-10')` for 0 in decimal(38,10)); money → `Decimal`; datetime2/datetimeoffset/time(7) → microseconds (the 7th digit is lost); datetimeoffset is tz-aware; UUID → `uuid.UUID`; bit → bool; sql_variant → raw bytes (`b'*\x00\x00\x00'` for 42); xml / nvarchar(max) / ntext → str; varbinary / image / rowversion / hierarchyid / geometry → bytes. SQL Server rejects `N'2026-10-18 12:34:56.123000'` for a `datetime` (error 241) but accepts `.123`.
- **Speed.** 100,000 rows in 500-row pages with conversion and `encode_row`: 0.23 s, max page 2 ms. The describe query takes ~1 ms and the state query ~0.4 ms on the dev server.
- **Permissions.** `CONNECTIONPROPERTY('encrypt_option')` and `sys.dm_exec_connections` need VIEW SERVER STATE, so the adapter cannot verify encryption for a normal login; FreeTDS's `require` fails the login itself when encryption is impossible.

```python
@dataclass(frozen=True, slots=True)
class ColumnKind:
    name: str  # what the grid header shows: the server's type name, or a guess
    category: ColumnCategory


_N, _B, _D, _T, _X = (ColumnCategory.NUMBER, ColumnCategory.BOOL, ColumnCategory.DATETIME, ColumnCategory.TEXT,
                      ColumnCategory.BINARY)
_CATEGORY_BY_TYPE: dict[str, ColumnCategory] = {
    **dict.fromkeys(("bigint", "int", "smallint", "tinyint", "decimal", "numeric", "money", "smallmoney", "float", "real"), _N),
    "bit": _B,
    **dict.fromkeys(("date", "datetime", "datetime2", "smalldatetime", "datetimeoffset", "time"), _D),
    **dict.fromkeys(("char", "varchar", "nchar", "nvarchar", "text", "ntext", "xml", "uniqueidentifier", "sysname"), _T),
    **dict.fromkeys(("binary", "varbinary", "image", "timestamp", "rowversion", "sql_variant", "hierarchyid", "geometry",
                     "geography"), _X),
    "json": ColumnCategory.JSON,
}
_GUESSED: dict[type, ColumnKind] = {  # exact types: bool is not taken for int, datetime is handled before date
    bool: ColumnKind("bit", _B), int: ColumnKind("int", _N), float: ColumnKind("float", _N),
    Decimal: ColumnKind("decimal", _N), str: ColumnKind("nvarchar", _T), bytes: ColumnKind("varbinary", _X),
    date: ColumnKind("date", _D), time: ColumnKind("time", _D), UUID: ColumnKind("uniqueidentifier", _T),
}
# pymssql's DB-API type codes for a column that is NULL in every looked-at row. Code 2 (BINARY) also covers dates and
# UUIDs, so it says nothing.
_BY_CODE = {1: ColumnKind("nvarchar", _T), 3: ColumnKind("int", _N), 4: ColumnKind("datetime", _D), 5: ColumnKind("decimal", _N)}
_UNKNOWN = ColumnKind("unknown", ColumnCategory.OTHER)


def described_kind(system_type_name: str) -> ColumnKind:
    """From sys.dm_exec_describe_first_result_set's system_type_name, e.g. `decimal(38,10)`."""
    base = system_type_name.split("(", 1)[0].strip().lower()
    return ColumnKind(system_type_name, _CATEGORY_BY_TYPE.get(base, ColumnCategory.OTHER))


def guessed_kinds(header: Sequence[tuple], rows: Sequence[Sequence[Any]]) -> list[ColumnKind]:
    """A result set the describe query did not cover: each column's first non-NULL value decides."""
    kinds: list[ColumnKind] = []
    for i, column in enumerate(header):
        value = next((row[i] for row in rows if row[i] is not None), None)
        if isinstance(value, datetime):
            kinds.append(ColumnKind("datetimeoffset" if value.tzinfo else "datetime2", _D))
        elif value is not None:
            kinds.append(_GUESSED.get(type(value), _UNKNOWN))
        else:
            kinds.append(_BY_CODE.get(column[1], _UNKNOWN))
    return kinds


def _timespec(microsecond: int) -> str:
    """As few fractional digits as the value needs: a `datetime` literal takes at most three (error 241)."""
    return "seconds" if microsecond == 0 else "milliseconds" if microsecond % 1000 == 0 else "microseconds"


_CONVERTERS: dict[type, Callable[[Any], Any]] = {
    Decimal: lambda v: format(v, "f"),  # plain digits: Decimal('0E-10') is 0.0000000000
    datetime: lambda v: v.isoformat(sep=" ", timespec=_timespec(v.microsecond)),  # keeps a datetimeoffset's offset
    date: date.isoformat,
    time: lambda v: v.isoformat(timespec=_timespec(v.microsecond)),
    UUID: lambda v: str(v).upper(),  # as SSMS shows it
}


def convert_row(row: Sequence[Any]) -> list[Any]:
    return [convert(value) if (convert := _CONVERTERS.get(type(value))) else value for value in row]
```

```python
class _Phase(StrEnum):
    IDLE = "idle"  # no statement on the connection
    EXECUTING = "executing"  # the worker waits for the server: the describe query, execute, the next result set
    STREAMING = "streaming"  # rows are being read, or wait unread (a paused page)


def _text(raw: bytes | str | None) -> str:
    return raw.decode("utf-8", errors="replace") if isinstance(raw, bytes) else (raw or "")


def server_text(exc: Exception) -> str:
    """The server's message without pymssql's "DB-Lib error message 20018, severity N: …" tail; "" when there is none.
    MSSQLDatabaseException carries it in `.text` (bytes); MSSQLDriverException only in its args."""
    raw = getattr(exc, "text", None)
    if raw is None:
        first = exc.args[0] if exc.args else ""
        raw = first[1] if isinstance(first, tuple) and len(first) > 1 else str(first)
    text = _text(raw).split("DB-Lib error message", 1)[0].strip()
    return "" if text in ("", "Unknown error") else text


class MssqlResult(StatementResult):
    """The result sets of one batch, read on the worker thread."""

    def __init__(self, owner: "MssqlConnection", described: list[ColumnKind] | None) -> None:
        self._owner = owner
        self._closed = False
        self._exhausted = False  # every result set read, or the batch failed
        self._open_set(described)

    def _open_set(self, described: list[ColumnKind] | None) -> None:
        header = self._owner.header()
        self._buffer: list[tuple] = []
        self._rows_done = header is None
        if header is None:
            self._columns = None
            return
        self._iter = self._owner.rows()
        names = [h[0] for h in header]
        if described is not None and len(described) == len(names):  # run() already matched the described names
            kinds = described
        else:
            self._buffer = self._read(_TYPE_PEEK)
            kinds = guessed_kinds(header, self._buffer)
        self._columns = [
            ColumnMeta(name=name or _NO_COLUMN_NAME, type_name=kind.name, category=kind.category)
            for name, kind in zip(names, kinds)
        ]
        if any(kind.name == "sql_variant" for kind in kinds):
            self._owner.note(ServerMessage(severity=MessageSeverity.INFO, text=SQL_VARIANT_HINT))

    def _read(self, n: int) -> list[tuple]:
        rows: list[tuple] = []
        try:
            while len(rows) < n:
                if self._owner.cancel_requested:  # a plain attribute read; cancel() sets it under the owner's lock
                    self._exhausted = True
                    raise self._owner.stop_stream()
                row = next(self._iter, None)
                if row is None:
                    self._rows_done = True
                    break
                rows.append(row)
        except driver.ERRORS as exc:  # an error later in the batch
            self._exhausted = True
            raise self._owner.statement_error(exc) from exc
        return rows

    def columns(self) -> list[ColumnMeta] | None:
        return self._columns

    def fetch(self, n: int) -> list[list[Any]]:
        if self._columns is None or self._closed:
            return []
        rows, self._buffer = self._buffer[:n], self._buffer[n:]
        if len(rows) < n and not self._rows_done:
            rows += self._read(n - len(rows))
        return [convert_row(row) for row in rows]

    def affected_rows(self) -> int | None:
        count = self._owner.rows_affected()
        return count if self._columns is None and count >= 0 else None

    def next_result(self) -> bool:
        """The worker asks only once the current set is read to its end (pymssql's nextresult() would otherwise drain
        it while the phase says EXECUTING)."""
        if self._closed or self._exhausted:
            return False
        while self._columns is not None and not self._rows_done:
            self._read(1000)
        try:
            more = self._owner.next_set()
        except StatementError:
            self._exhausted = True
            raise
        if not more:
            self._exhausted = True
            self._owner.end_statement()
            return False
        self._open_set(None)
        return True

    def take_messages(self) -> list[ServerMessage]:
        return self._owner.take_pending()

    def close(self) -> None:
        if self._closed:
            return
        self._closed = True
        self._owner.finish_result(self, complete=self._exhausted)
```

`run()` passes the described kinds only when the described column names equal the runtime header's names: the DMF predicts the first result set from the batch text, and a procedure or an IF can make the real first set a different one. Every other result set guesses its types from its first ≤ 100 rows.

In `MssqlConnection`:

```python
    def __init__(
        self, conn: driver.Connection, *, spid: int, database: str | None, read_only: bool,
        state: tuple[int, int, bool],  # (@@TRANCOUNT, XACT_STATE(), IMPLICIT_TRANSACTIONS) read at open
    ) -> None:
        self._conn = conn
        self._spid = spid
        self._database = database
        self._read_only = read_only  # application-level only (spec §3.4): logged, never enforced here
        self._lock = threading.Lock()  # guards _phase and cancel_requested; held across a cross-thread cancel
        self._phase = _Phase.IDLE
        self.cancel_requested = False
        self._result: MssqlResult | None = None  # the open result until it is read to its end or closed
        self._listener: MessageListener | None = None
        self._pending: deque[ServerMessage] = deque(maxlen=1000)
        self._lost = False
        self._stale = False  # True once the cached state may be out of date: re-read when nothing is unread
        self._trancount, self._xact_state, self._implicit = state
        conn.set_msghandler(self._on_message)

    # ---- phases and cancel ----

    def _set_phase(self, phase: _Phase) -> bool:
        """Change the phase under the lock, so a cross-thread cancel in progress finishes first. Returns whether a
        cancel reached this statement. Leaving IDLE starts a statement: the flag belongs to it alone (R-03a-P4)."""
        with self._lock:
            if self._phase is _Phase.IDLE and phase is _Phase.EXECUTING:
                self.cancel_requested = False
            self._phase = phase
            return self.cancel_requested

    def end_statement(self) -> None:
        with self._lock:
            self._phase, self.cancel_requested = _Phase.IDLE, False
        self._result = None
        self._stale = True

    def cancel(self) -> None:
        """Any thread (spec §3.6). EXECUTING: the attention goes out across threads, which the probes show ends a
        WAITFOR in about 1 s and keeps the session. STREAMING: only the flag; the worker cancels before its next row
        (a cross-thread cancel while rows stream can hang). IDLE: nothing runs, nothing to do: a flag now would
        cancel the next statement."""
        with self._lock:
            if self._phase is _Phase.IDLE:
                return
            self.cancel_requested = True
            if self._phase is _Phase.STREAMING:
                logger.info("SQL Server cancel flagged for SPID {}: the stream stops at its next row", self._spid)
                return
            started = time.monotonic()
            try:
                self._conn.cancel()
            except Exception as exc:  # never let a cancel raise; the flag still stops the stream
                logger.warning("SQL Server cancel of SPID {} failed: {}: {}", self._spid, type(exc).__name__, exc)
                return
            logger.info("SQL Server cancel sent to SPID {} in {:.0f} ms", self._spid, (time.monotonic() - started) * 1000)

    def stop_stream(self) -> StatementCancelled:
        """Worker thread: end the statement whose cancel was flagged (or whose rows are no longer wanted)."""
        started = time.monotonic()
        try:
            self._conn.cancel()
        except driver.ERRORS as exc:  # e.g. an error the server sent before the attention: the statement ends anyway
            logger.warning("Stopping the SQL Server stream on SPID {} reported: {}", self._spid, server_text(exc) or exc)
        self.end_statement()
        logger.info("SQL Server stream on SPID {} stopped in {:.0f} ms", self._spid, (time.monotonic() - started) * 1000)
        return StatementCancelled()

    def finish_result(self, result: MssqlResult, complete: bool) -> None:
        if self._result is not result:
            return
        if not complete:
            self.stop_stream()  # an attention on this thread: the transaction and #temp tables stay (probed)
        else:
            self.end_statement()

    # ---- execution ----

    def run(self, sql: str) -> StatementResult:
        if self._result is not None:  # the worker closes every result first; never send over unread rows
            self._result.close()
        self._refresh_state()  # the describe query needs the current mode; normally fresh (the worker reads it per request)
        self._stale = True
        self._set_phase(_Phase.EXECUTING)
        try:
            described = self._describe(sql)
            if self.cancel_requested:
                raise StatementCancelled()
            self._conn.execute_query(sql)  # sends the batch verbatim (no params: `%` untouched), waits for set 1
        except StatementCancelled:
            self.end_statement()
            raise
        except driver.ERRORS as exc:
            raise self.statement_error(exc) from exc
        if self._set_phase(_Phase.STREAMING):  # it ended just as the cancel arrived
            raise self.stop_stream()
        header = self.header()
        names = [h[0] for h in header] if header else []
        kinds = [kind for _, kind in described] if described and [name for name, _ in described] == names else None
        self._result = MssqlResult(self, kinds)
        return self._result

    def next_set(self) -> bool:
        if self._set_phase(_Phase.EXECUTING):
            raise self.stop_stream()
        try:
            more = bool(self._conn.nextresult())
        except driver.ERRORS as exc:
            raise self.statement_error(exc) from exc
        if self._set_phase(_Phase.STREAMING):
            raise self.stop_stream()
        return more

    def _describe(self, sql: str) -> list[tuple[str, ColumnKind]] | None:
        """The first result set's column names and types, from sys.dm_exec_describe_first_result_set: same connection,
        before the batch, inside the EXECUTING phase (cancellable like it). The DMF reports a batch it cannot describe
        as error rows instead of raising, so an XACT_ABORT ON transaction never dies of it, unlike
        sp_describe_first_result_set (probed). In manual mode a SELECT from the DMF would open an implicit transaction,
        so the mode is switched off around it in the same round trip."""
        if len(sql) > _DESCRIBE_LIMIT:
            return None
        query = (
            "SELECT name, system_type_name, error_number FROM sys.dm_exec_describe_first_result_set("
            f"{quote_literal(Dialect.TSQL, sql)}, NULL, 0) ORDER BY column_ordinal"
        )
        if self._implicit:
            query = f"SET IMPLICIT_TRANSACTIONS OFF; {query}; SET IMPLICIT_TRANSACTIONS ON"
        try:
            found = catalog.rows(self._conn, query)
        except driver.ERRORS as exc:
            logger.debug("Describing a SQL Server batch failed ({})", type(exc).__name__)
            return None
        if not found or any(error is not None for _, _, error in found):
            return None
        return [(name or "", described_kind(type_name)) for name, type_name, _ in found]
```

Messages, state and errors:

```python
    def set_message_listener(self, listener: MessageListener | None) -> None:
        self._listener = listener
        if listener is not None:
            self._pending.clear()  # messages from before this request belong to no statement shown now

    def note(self, message: ServerMessage) -> None:
        listener = self._listener
        if listener is not None:
            listener(message)
        else:
            self._pending.append(message)

    def take_pending(self) -> list[ServerMessage]:
        taken = list(self._pending)
        self._pending.clear()
        return taken

    def _on_message(self, state: int, severity: int, server: bytes, procedure: bytes, line: int, text: bytes) -> None:
        """pymssql calls this on the thread inside the driver call, for every message: errors too (severity >= 11),
        which pymssql then raises as the statement's error, so they are left to it. Never raises into the driver."""
        try:
            if severity < 11:
                self.note(ServerMessage(severity=MessageSeverity.INFO, text=_text(text)))
        except Exception:
            logger.exception("SQL Server message handler failed")

    def _refresh_state(self) -> None:
        """One round trip, only after something may have changed the state and only with nothing unread."""
        if not self._stale or self._result is not None or self._lost:
            return
        try:
            row = catalog.first_row(self._conn, _STATE_QUERY)
        except driver.ERRORS as exc:
            self.translate_error(exc)  # marks a dead connection as lost
            logger.debug("Could not read the SQL Server transaction state on SPID {}: {}", self._spid, server_text(exc))
            return
        trancount, xact_state, implicit, database = row
        self._trancount, self._xact_state, self._implicit = int(trancount), int(xact_state), bool(implicit)
        self._database = database
        self._stale = False

    def in_transaction(self) -> bool:
        self._refresh_state()
        if self._lost:
            return False
        # Ruling 17: rows are unread, so no query: in manual mode a result long enough to pause comes from a table,
        # and reading a table opens an implicit transaction.
        return self._trancount > 0 or (self._implicit and self._result is not None)

    def transaction_failed(self) -> bool:
        self._refresh_state()
        return not self._lost and self._trancount > 0 and self._xact_state == -1  # XACT_STATE() alone is not enough

    def autocommit(self) -> bool:
        self._refresh_state()  # @@OPTIONS also catches a typed SET IMPLICIT_TRANSACTIONS or SET ANSI_DEFAULTS
        return not self._implicit

    def statement_error(self, exc: Exception) -> StatementError:
        """The error of the user's statement (run, fetch, next result): the only place a cancel can show."""
        error = self.translate_error(exc, statement=True)
        self.end_statement()
        return error

    def translate_error(self, exc: Exception, statement: bool = False) -> StatementError:
        """Commit, rollback, auto-commit and state queries never report "cancelled" (R-03a-P4)."""
        number = int(getattr(exc, "number", 0) or 0)
        text = server_text(exc)
        if statement and self.cancel_requested:
            return StatementCancelled()
        severity = int(getattr(exc, "severity", 0) or 0)
        if self._lost or number in _CONNECTION_LOST_NUMBERS or severity >= _FATAL_SEVERITY or (number == 0 and not self._alive()):
            self._lost = True
            return StatementError(
                "Connection to the server was lost" + (f": {text}" if text else ""), code="connection_lost"
            )
        if number == 0:
            return StatementError(text or "SQL Server ended the statement without an error message")
        line = int(getattr(exc, "line", 0) or 0)
        procedure = _text(getattr(exc, "procname", b""))
        message = text + (_PROCEDURE_LINE.format(procedure=procedure, line=line) if procedure else "")
        position = ErrorPosition(line=line, column=1) if line > 0 and not procedure else None
        return StatementError(message, code=str(number), position=position)

    def _alive(self) -> bool:
        """pymssql reports a dead connection as error 0 "Unknown error" and keeps `connected` True: ask once."""
        try:
            self._conn.execute_non_query("SELECT 1")
            return True
        except driver.ERRORS:
            return False
```

`header()` is `self._conn.get_header()`, `rows()` is `self._conn.get_iterator(driver.ROW)`, `rows_affected()` is `self._conn.rows_affected`.

The rest of `MssqlConnection` follows these rules:
- **`set_autocommit(enabled)`:** no-op when `self.autocommit() == enabled`; `transaction_open_error()` when `self.in_transaction()`; else `execute_non_query(f"SET IMPLICIT_TRANSACTIONS {'OFF' if enabled else 'ON'}")`, set `_implicit = not enabled`, log INFO `"Auto-commit {} on SQL Server SPID {}"`. Errors go through `translate_error(exc)` (never `statement=True`).
- **`commit()`:** `execute_non_query("WHILE @@TRANCOUNT > 0 COMMIT TRANSACTION")` (every nesting level: Ruling 18). **`rollback()`:** `execute_non_query("IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION")`. Both set `_stale = True` and translate errors without `statement`.
- **`server_info()`:** `catalog.first_row(conn, "SELECT @@VERSION, DB_NAME(), SUSER_SNAME()")`. `version` is the first line of `@@VERSION`, stripped. It refreshes `_database` and returns `ServerInfo(engine=Engine.MSSQL, …)`. **`current_database()`** returns `_database`, which the state query keeps current after a typed `USE`.
- **`list_children` / `object_detail`:** raise `ValidationFailed(f"Connection is bound to database '{self._database}', not '{path[0].name}'")` when `path` is non-empty and `path[0].name != self._database` (as PostgreSQL does), then delegate to `introspection` with `self._conn`. **`schema_snapshot`** delegates to `schema.build_snapshot`.
- **`close()`:** `self._conn.close()`, suppressing driver errors.

`MssqlAdapter.open(profile, endpoint, password, database)`:
1. `ValidationFailed("Not a SQL Server profile")` unless it is a `ServerProfile` with an endpoint.
2. `params = connect_params(...)`; when `params.tds_section`, `kwargs = {**params.kwargs, "server": freetds.active().section_for(params.tds_section)}`.
3. `conn = driver.connect(CONNECT_TIMEOUT_S, **kwargs)`:
   - `driver.ERRORS` → `ConnectionFailed(_login_failure(exc, endpoint))`:
     - when a TCP connection to `endpoint` (3 s) fails: `f"Could not reach SQL Server at {endpoint.host}:{endpoint.port}: {os_error}"`;
     - else `server_text(exc)` followed by a newline and `_LOGIN_HINT` when that text contains `"Login failed"`;
     - else `_LOGIN_HINT` alone (never pymssql's number or a stale reason, Review Focus 5).
   - `TypeError` / `ValueError` → `ConnectionFailed(f"Invalid SQL Server connection setting: {exc}")`.
4. In a try block that closes `conn` on any failure: `spid, trancount, xact, implicit, db = catalog.first_row(conn, _OPEN_QUERY)`.
5. Log INFO `"Connected to SQL Server {}:{} db={} tls={} spid={}{}"`: the host is `endpoint.tls_server_name or endpoint.host`, the TLS mode is the profile's, `" read_only=True (enforced by DbaGuy only)"` when set.
6. Return `MssqlConnection(conn, spid=int(spid), database=db, read_only=profile.read_only, state=(int(trancount), int(xact), bool(implicit)))`.

`parse_url(url)` returns `parse_mssql_url(url)`. Register the adapter in `container.default_registry()`.

## Spec issues found while planning

- §2 and §3.6 name `sp_describe_first_result_set`. Under `SET XACT_ABORT ON` in an open transaction, its error rolled the user's transaction back (probed). `sys.dm_exec_describe_first_result_set`, which feature-priorities §7 names, returns error rows instead. It opens an implicit transaction in manual mode, so it is wrapped (Ruling 19). The spec should name the DMF.
- §3.6 commit `IF @@TRANCOUNT > 0 COMMIT` leaves nested transactions open (`@@TRANCOUNT` 3 → 2, probed); the plan uses `WHILE` (Ruling 18).
- §3.6 maps prefer → `request`. Against a server that does not force encryption, `request` encrypts only the login (probed). The mapping stays (it is FreeTDS's meaning), and the dialog label says so.
- §3.6 says to check whether pymssql's parameters cover CA and host-name checks: they do not. `encryption` takes only default/off/request/require, so freetds.conf sections are needed. `strict` is unavailable either way, and verify-* without a CA file cannot use the keychain (Ruling 22).
- §3.2's T-SQL body rule `tsql_block` (BEGIN…END, TRY/CATCH) is unnecessary because `;` never splits T-SQL. What the classifier needs is "a module definition owns its batch" (Ruling 7).
- §3.3/§3.4 say sqlglot parses a batch statement by statement. It does so only with `;` between statements: `DECLARE @x INT\nDELETE FROM t` is one `Command` (probed). A lexical statement cutter is needed (Ruling 8), and the table-data filter guard needs a T-SQL rule (Ruling 10). Neither is in the spec.
- §3.6 lists DB-Lib errors 20003/20004/20006/20009/20047 as `connection_lost`. With `min_error_severity = 11` they never surface, because their severities are ≤ 10: a dead connection is error 0 "Unknown error" (probed; Ruling 13). Login errors are unreliable after the first failure (Ruling 14).
- §3.6 types: "Decimal → str", "datetimeoffset → ISO". Also needed: `datetime` values written with at most three fractional digits (error 241) and plain-digit decimals (`0E-10`). The 7th fractional digit is lost (Ruling 20).
- §3.8 "GO n is sent n times" does not cover `GO 0` (sqlcmd runs zero times) or very large n (Ruling 6).
- §3.6 says `fetch()`/`next_result()` check the flag. The server holds a result's last packet until the batch moves on, so a fetch can wait for later statements. A flag-only cancel cannot stop them: a documented limit (Ruling 15).
- §4: `sqlcmd` needs `-I` for the seed's filtered index, and `compose up --wait` does not wait for the `mssql-init` one-shot. Health is therefore the seed's last table (Ruling 28).
- §1/§3.6 do not mention that pymssql reports one affected-rows count per batch (Ruling 34) or that a mid-batch error hides later results while the batch runs on (Ruling 33). Both are documented limits.
- §3.6 says closing an unread result with `cancel()` does not affect the transaction. That holds with XACT_ABORT OFF, the default the spec assumes. Under a user's `SET XACT_ABORT ON`, an attention rolls the transaction back (SQL Server's documented behaviour; Ruling 36).
