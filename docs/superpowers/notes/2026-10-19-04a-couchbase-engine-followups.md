# Plan 04a (Couchbase engine) — rulings and follow-ups

Plan: `docs/superpowers/plans/2026-10-18-04a-couchbase-engine.md` (assumptions A1–A22 and planning rulings P1–P48 at its end). Spec: `docs/superpowers/specs/2026-10-18-04-couchbase-design.md`. Executed with subagent-driven development: a pre-flight scan (P33–P48), 13 tasks plus Task 6b, each reviewed (most through a fix round), every review also checked against the researched pain points; a timing-test hardening side task; a final Opus whole-branch review, one fix wave (F1–F6) and a scoped re-review. Commits beac4c1..4ad8fe1 on `feat/04-couchbase` (38 commits, 3909 backend tests passed, 0 skipped). The branch stays open for 04b and 04c and merges to `main` after ④, as ③ did.

## Outcome against the pain points (feature-priorities §2, §3, §4, §8)

- Q1 light and fast: no SDK, no new dependency; sidecar 48,896 → 49,020 KB; app cold start 1.1–1.2 s (the first launch after a rebuild about 4 s) and footprint 175–177 MB, the same as 03b. Frozen sidecar against the dev cluster: first page (500 rows, `*`) 31–64 ms (103 ms once, on the very first query after a start; target < 100 ms); 300-collection tree 39 ms cold, 8–9 ms warm; 1M rows in pages of 10,000: RSS peak 99–104 MB, flat over repeats, footprint 91 MB (the Python SDK: 1.15 GB); 100k rows with cell encoding 0.76–1.12 s (budget 4 s). Costs: a `*` result waits for its first page (≤ 500 rows / 8 MiB) before showing rows; the dev cluster takes 1.2 GiB.
- Q2 never lose work / never hang: cancel of a long aggregate 3 ms with the server state `closed` (plain, TLS, SSH bastion); a cancel works at every moment (armed window, connect, status-line wait, head, mid-body, paused); rows read before an error, a cut connection or a server stop always reach the grid; a paused result is closed by DbaGuy 45–60 s after its first pause with a message and its rows kept, instead of being cut by the server at 77–86 s. The new arm/disarm step also closed a lost-cancel window in PG, MySQL, SQLite and SQL Server (all four lost a forced cancel before the fix, 0 after).
- Q3 trustworthy: exact int64/uint64/`1.10`/`1E+3`/`1e-400` (numbers travel as text), key order, MISSING apart from null, errors with the server's code, text and position; `readonly=true` on every request of a read-only profile and on every internal query, plus the classifier (≈ 13.7k hand-written and mutated statements against the server, 0 read-only escapes; the one exception is `UPDATE STATISTICS`, M1); TLS failures name their real cause; transactions refused, never half-supported; no password in any log; the format guard (all dialects) keeps ⌘⇧F from rewriting a string or a name.
- Q4 / Q5 / Q6: inside the §4 Won't list (no INFER at connect, no document editor yet); new capabilities are engine-neutral (`RunOptions`, arm/disarm, raw JSON export, format guard) and the other four engines passed unchanged (gen:api no diff, 298 formatter outputs with 0 false refusals); no new shortcut, IME and menus untouched.
- §4 Musts: 1 connection done (URL import, TLS modes with the cluster CA, SSH, node discovery; Capella SRV and Capella CA are out per §8); 2 tree done (bucket › scope › collection › index with state and DDL; context by click is 04b); 3 editor: split, run range, cancel, paging done, tab timeouts stay the worker's, picker and parameters are 04b; 4 results done (signature order, overflow column, metrics, Load more); 5 export done (CSV/JSON/JSONL streamed, JSON passthrough byte-exact); 6 documents are 04c; 7 EXPLAIN is 04b (04a runs EXPLAIN/ADVISE as plain results); 8 history done (per connection, records the query context).

## Rulings made during execution

- A1–A22: every one tried held except A13 (below); A7's answer was the cautious one (the server refuses NBSP, U+2003, U+3000, ZWSP and BOM as spaces → `unicode_spaces=False`); A12 holds with one exception (M1); A2, A3 are 04c's and A16 is 04b's. Results are in the plan's table.
- R-04a-X1 (5b05b22): a cancel landing after the worker's last flag check but before the adapter is inside `run()` was dropped by every engine. Fix: `arm_cancel()` / `disarm_cancel()` in the adapter contract (shared `adapters/cancel_window.py`; SQL Server maps it to its STARTING phase), not a re-issue loop, because re-issuing a PG cancel or a KILL could hit the next statement. New engines must implement it (CLAUDE.md).
- R-04a-6b1 (2c97dfc): the same gap existed inside PG transactions (BEGIN/DECLARE/describe, then FETCH runs): the worker re-checks the flag after opening a READ and first in an export; PG and MySQL `take_over()` moved to just before the first send. A microsecond gap before the first send is accepted (a cancel needs a new connection first).
- R-04a-T3a/T3b (0571aef): `USE KEYS` holding a subquery is not a filter (only the keys expression is scanned); a FROM-first select is a READ (valid on the server, otherwise blocked read-only).
- R-04a-T4a (51330b5): MSSQL/MySQL timing tests scale to machine load, never product behaviour; no product bug found.
- R-04a-T7a (86ee013): a non-blocking, cancellable connect (a cancel waited for the connect timeout); DNS stays blocking. Review fixes in the same commit: a body cut inside a number never shows a wrong last row.
- R-04a-T8a (b5e4ed7): `*` alias expansion (D-04-1 condition 3 relaxed, spec 60b7cbd): expand when some first-page alias value is a non-empty object, other rows' `*` part goes to the overflow cell as sent; else one plain column. Without it `app.users` (objects mixed with scalars) showed one `d` column.
- R-04a-T8b: lone surrogates become JsonText or escaped column names, so the WebSocket send never fails.
- R-04a-T9a (d583d7e): refuse `@` in a URL's path, query and fragment (after NFKC) and empty ports, because an unencoded `/ ? #` after a digits-first password leaked a password tail into fields and the log; discovery also got one overall deadline, host validation, dedupe and a cap of 64, and fixed texts for http.client errors.
- Task 6 review I1 (7deef53, no ruling): a parameter number with a huge exponent passes the shape check (`parse_float=str`); the server judges its range.
- R-04a-T11a: keep `PAUSED_RESULT_MAX_IDLE_S = 45` for 04a (A13 failed, so the planned 120 s would be cut by the server first); the bounded read-ahead is 04b's.
- R-04a-T11b (36a90f3): the idle clock runs from a result's first pause and a Load more does not restart it: the server's stall clock does not reset when a 500-row Load more is served from 17–37 MB of buffers (measured: state `fatal` at 77–83 s). Cost: an active Load-more user gets the result closed 45–60 s after the first pause (rows kept, clear text).
- R-04a-F1 (b0643d9, 5f4f08f): the TLS hint comes from the ssl error kind (hostname mismatch, with verify codes 62 and 64; unknown issuer; wrong version number; else none); a 404 from the query endpoint says the port is not the query service; plain HTTP to a TLS port says it may expect TLS.
- R-04a-F2 (efc5f5a): a float stays a Python float only when `repr == text`, no `e`/`E`, not ending `.0`; else JsonText (JavaScript showed `1.0` as 1 and `1e+16` as 10000000000000000, so grid and export disagreed).
- R-04a-F3 (b0643d9): internal `query()` (catalog, snapshot, server info) sends `timeout: 30s` and has a 40 s client read deadline; user statements get none. A stalled catalog query used to hold the metadata worker for 120 s and then leak a thread and a socket.
- F4–F6, no ruling: `one_line` moved to `sql/jsontext.py` (`sql/` imports no adapter); CLAUDE.md's `http` wording; the SSL hint says verify-ca/verify-full need the cluster's CA file (the bundled OpenSSL's default bundle exists only with Homebrew).
- R-04a-C1…C21 passed between tasks and were all applied inside 04a (arm the cancel timer before `run()`; no resend after a cancel; ADVISE probes use `app.orders`; `namespace` is a reserved word; `_system` is never listed on 7.6.12; transaction refusal per split statement; catalog rows decode with plain `json.loads`; …). The lasting ones are in CLAUDE.md.

## Incidents

- A13 failed: 7.6.12 kills a request whose client stopped reading 77–86 s after the pause (error 1203 `service.slow_client`, state `fatal`; four runs: 77.3, 77.7, 85.0, 86 s). The planned 120 s limit became 45 s (R-04a-T11a/T11b); spec R-04-6, §3.7.4 and the plan's Global Constraints were rewritten.
- Task 11 review I1: a Load more restarted DbaGuy's clock but not the server's, so an active user would have got `connection_lost` instead of the clean close. Fixed by T11b, with a live test that does a Load more mid-pause.
- Task 11 review M1: `UPDATE STATISTICS` (and `ANALYZE`) runs under `readonly=true` on 7.6.12 and writes optimizer statistics into `_system._query`; everything else probed is refused with 1000 (Task 3's probe saw 12003 for `FLUSH COLLECTION`, the later review a plain refusal). The classifier is the only wall for these two, so it blocks them; CLAUDE.md, the plan's A12 row and the spec say so.
- Task 9 review F1 (Medium, fixed before merge, d583d7e): an unencoded `/ ? #` after a digits-first or empty-port password put a password tail into a field and the log. Now refused before parsing or logging, pinned by 12 leaky URLs under a log sink at level 0.
- A flaky SQLite cancel test turned out to be a real lost cancel (1.3 % in a WebSocket harness: sqlite3 clears an `interrupt()` that lands while the statement is parsed). Fixed in 584d752 (0/6,000 lost after); `tests/conftest.py` gained a 120 s per-test SIGALRM timeout with a stack dump. This led to X1.
- Machine load reached about 102 with several agents plus the hardening agent's busy loops; MSSQL and MySQL timing tests flaked (a different one per run, each green alone). Hardened in 51330b5; rule from then on: at most 2 test-running agents. Shared working tree: a full run spun over 10 minutes on another agent's uncommitted SQLite work and another saw 5 failures in an untracked test file, so reviews ran full suites from clean worktrees and every agent staged by path.
- The Task 3 reviewer left a prepared statement `rev04a_p1` (`PREPARE … DELETE … USE KEYS 'rev04a-none'`, a non-existent key) in the dev cluster's `system:prepareds`. Its cleanup DELETE was refused by the permission layer, so the controller did not run it either. In memory only, gone at the next node restart.
- Leftover optimizer statistics `cbo::…app.orders` and `app.users(histogram)zz_t3_none` from the `UPDATE STATISTICS` probes (M1); dev cluster only, harmless.
- Probe leftovers, all removed by exact name: Task 1's temporary collection `zz_t1_probe` (created and dropped four times), Task 11's `zz_never` document in `app.orders` and six `zz_p_*` prepared statements. The dev cluster was recreated by someone else while Task 3's probes ran (they were only EXPLAIN, readonly or non-matching-key statements).
- 0 native crash reports: DiagnosticReports holds no Python or DbaGuy report from 04a (no SDK, standard library only). Task 13 stopped its frozen sidecars by exact PID and the app data directory's mtime was unchanged before and after.

## Deferred minor findings

- Lexer and guard: `x$y` and `$1abc` lex differently from the server (same span); a trailing space-like character at a statement edge is dropped (all dialects); the MySQL `/*! */` guard compares squeezed text; a lone `\r` is a character to the server but a line break to CodeMirror, so an error mark could be off on such text (not checked in Task 12).
- Classification: `BEGIN` alone, `EXECUTE` and other `SET` are UNKNOWN (blocked read-only, fail closed); `EXPLAIN FUNCTION` was not probed under `readonly`; `FLUSH COLLECTION` answered 12003 instead of 1000 in Task 3's probe and a plain refusal later; the classifier blocks it either way.
- Values: `x IN [1e400]` written as an expression is evaluated by the server as a float (`+Infinity`; only stored values keep their text); a JSON-array export keeps every byte of a passthrough document by design (R-04-15) while JSONL squeezes whitespace outside strings; CSV cannot tell NULL from MISSING (both empty).
- HTTP and parser: DNS stays blocking at open and in discovery; the parser's doubling rule can hold one big row until more data arrives; a malformed token at the very end of a body reads as a cut response (P32); a response cut by a server-side 1203 kill has no metrics (shows `connection_lost`; reachable only with the idle close disabled).
- Worker: two `_state_lock` takes in `_finish`/`_fail` (optional); an idle-closed result is recorded in History as ok (as for a result replaced by a new statement); a result that fits the server's buffers is also closed at 45 s although the server finished it (D-04-12 design); the 45 s limit costs an active Load-more user the result (T11b).
- Contract nits: `PlanFormat` alias defined once; the keep-alive DEBUG text lost the engine name; `QueryContext` could live in `domain/query_context.py`; `ServerInfo.current_user` shows the server's form (`builtin:dbaguy`, `local:dbaguy_reader`); the CodeMirror SQL++ keyword list repeats `SQLPP_RESERVED` (P26).
- Discovery: IDN seeds skip discovery and use the seeds; `nodes.py` imports `http._connect` (rename later); a compromised seed can steer credentials to any discovered host (accepted in the spec, TLS verification limits it); multi-node maps are fixture-tested only.
- Catalog and tree: generated `WITH` has no `num_partition` / `nodes` (not verifiable on one node); the rows-then-require helper is duplicated; a limited user sees a `_default` scope that expands to nothing; "No indexes shown" cannot tell a collection with no index from a missing privilege.
- Frontend: Run for an engine without transactions no longer waits for `session_state.autocommit` (it still waits for the first `session_state`); the cut-value toast now shows on every engine (accepted, correct).
- Measurements: the 1M-row RSS growth depends on the baseline (8 MB from a warm sidecar, 22–58 MB after macOS trims an idle one; the peak is 99–104 MB either way), so the spec's "< 30 MB" holds literally only from a warm baseline.
- Docs: the plan's historical Task 11 and Task 13 text still says 120 s / "2 minutes", and the spec's file layout and the plan still place `jsontext` under `adapters/couchbase/` (historical records, left alone).
