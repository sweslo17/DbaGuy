## Outcome against the pain points (feature-priorities §2, §3, §4, §8)

- Q1 light and fast: no dependency; sidecar 49,020 → 49,100 KB (+80 KB, stdlib only); app cold start 0.98–1.06 s (first launch after a rebuild 2.40 s) and footprint 163–167 MB with backend 74–77 MB (04a: 1.1–1.2 s, 175–177 MB, 72–75 MB). Paging 1M rows: RSS growth 14–26 MB from a fresh sidecar that ran one query (target < 30 MB), peak 112 MB (fresh) / 104 MB (used, as 04a), footprint 94–98 MB (04a 91 MB); the fresh peak is 8–13 MB higher because a paused result now holds up to 8 MiB.
  - Cost: one 20 MiB document peaks at 320–540 MB of Python allocations in 04a's response parser (carried to 04c); each paused Couchbase result may hold 8 MiB.
- Q2 never lose work / never hang: a result that fits the 8 MiB budget is read to its end while paused and is never closed (`events`, 1.7 MB, loaded 10,000 more rows after 70 s, plain and TLS; the server's request finished 3 s after the pause), which removes 04a's worst cost (an active Load-more user lost the result at 45–60 s); a larger one closes 45–60 s after reading stops with the message and its rows kept (100 M-row stream: 53 s, server state `closed`, never `fatal`); Cancel, Discard, Load more and closing a tab are never held behind a read-ahead step (B33); parameter drafts cannot make a workspace save fail (B40) and a bad saved tab is repaired with its buffer kept; a detail tab recovers by itself once the profile is unlocked (Task 12b).
  - Cost: a large paused result still closes at 45–60 s (B42).
- Q3 trustworthy: parameters stay exact (`9007199254740993` + 1 gives `…994`); a number the server would round is flagged by parameter name and never by value, one beyond a double is refused by name; the int64 rounding rule agrees with the server on 42 of 43 live literals (the 43rd is flagged on purpose); EXPLAIN flags follow the researched rules and an unreadable plan shows `unknown`, never a guess; sampled paths are shown as SQL++ writes them and the caps say which one was hit; binary documents are told apart (`META().type`, A24); no parameter value reaches a toast or a log (Task 10 review) and a TRACE sink showed no sampled value or field name (Task 7 review); a server error that echoes SQL literals is logged without its message.
- Q4 / Q5 / Q6: inside the §4 Won't list (sampling is manual and sized by a setting, no INFER at connect, the plan is a tree not a graph, no document editor yet); new capabilities are engine-neutral or Couchbase-gated and the other four engines are unchanged (read-ahead is default-off, `gen:api` no diff, completion for the other dialects byte-identical over 662k results, ⌘P and describe identical); the shared UI changes (engine icons, the tab strip, one unlock dialog per profile) reach every engine. ⌘E is new and is taken on every query tab (nothing outside Couchbase); ⌘↵ and ⌘⇧↵ from a parameter field are IME-guarded (a synthetic composing keydown runs nothing) and the field's text commits at `compositionend`.
- §4 Musts: 2 tree (context by pointer click, browse tab by double-click) done; 3 editor (per-tab context picker, parameters panel) done; 5 export runs in the context and with the parameters of its execution; 7 EXPLAIN done (Explain, Run with profile, Get index advice, findings by node id); 8 history reopens a tab in its context (B15); 1, 4 were 04a's; 6 documents are 04c.

## Rulings made during execution

- B42 (coordinator, pre-flight): an empty socket neither starts nor ends a stall (the planned B3 is withdrawn); only `DONE` or at least 16 MiB read since the stall began ends one. Draining the local socket does not mean the server's write finished (A23: about 5.5 MiB must be read to reset its clock); on a small-buffer link such as a VPN, B3 would restart DbaGuy's clock while the server's kept running and its kill (`connection_lost`) would come first.
  - Cost: a user who keeps loading more of a result larger than 8 MiB gets the clean close 45–60 s after the stall began unless 16 MiB was read since.
- B43: a committed live TLS read-ahead test (verify-ca, ordered Load more, a discard leaves the request `closed`), because decrypted bytes pending in OpenSSL had only a probe behind them.
- B44 (coordinator, on Task 2's first report): the 16 MiB reset applies in every step state, `WAITING` included, and bytes read by Load more count; without it a big Load more followed by a slow producer closed a result whose server was not stalled. `WAITING` still never starts a stall or clears one on emptiness alone.
- B45 (coordinator, on Task 4's first report): the worker never pauses a `plan` set before its first row. The profile set arrived paused with 0 rows whenever the grid filled the page (`LIMIT 500`, the commonest browse), so the plan view needed a Load more before it could draw. Other engines' paging is unchanged.
- B46 (Task 4 review): a number beyond a double in any parameter is refused by name (`invalid_params`; nothing is sent, no export file). The server's error 1040 echoed the number, which would reach History, and DbaGuy's texts never carry a parameter value (B10).
- B47 (coordinator, on Task 8's first report): under a bucket-only context a two-part SQL++ path is `scope.collection` of that bucket; under a scoped context or none it names nothing. Probed read-only: `FROM app.users` works with `default:dbaguy` and is "Ambiguous reference" with `default:dbaguy.app`.
- B48 (coordinator, after Task 9's browser check): only a pointer click on a tree node sets a tab's context. Arrow keys and a double-click's first click changed what the next ⌘↵ runs against without the user choosing it (Q3), so keyboard navigation does not, a click applies after 250 ms, a double-click on a collection cancels it, and a busy tab ignores it. ⌘P collection notes show only for engines that have a context.
- B49 (coordinator, Task 12): a sampled path is shown as SQL++ writes it (`FieldPath.display`, back-ticks from the backend's `quote_ident`), so a key with a dot, a space or `[]` is not read as nesting; the frontend never quotes.
- B50 (coordinator, Task 12): the 6-level depth cap is reported (`FieldSample.depth_capped`) because it was silent; `long_keys_skipped` is split from `paths_capped` so each note names its own cause.
- Task 9b (user: tab tops clipped by the classic macOS scrollbar, and engine icons): the workspace tab strip never draws a scrollbar (`scrollbar-none`, the wheel scrolls it sideways, the active tab scrolls into view, New query sits outside the strip). Icons are simple-icons CC0 paths for PostgreSQL, MySQL, SQLite and Couchbase and lucide's Server glyph for SQL Server (never Microsoft's logo); per-engine colour tokens, lightened in dark mode to at least 4.3:1 on the panel; icons in the tree, tabs, connection picker, History and ⌘P. The controller also pinned `+` outside the strip and made the engine label truncate before the profile name (a narrow sidebar had shrunk the name to 0 since ①).
- Task 12b (user: a detail tab stuck on "Enter the password" after a backend reload, pre-existing since ②): detail tabs share `RecoverableError` with query and table tabs (Retry, unlock dialog) and refetch by themselves when the profile is unlocked anywhere (`retryFailedExplorer`: errored children, detail and sampled-field queries only). Final wave (886ab2e): one unlock dialog per profile (`unlockPrompts` queue, `UnlockPromptHost`), because restored tabs of one locked profile each opened one.
- B31 (pre-flight): a read-ahead step reads the clock right after `read_ahead()` returns, then publishes the mark's `since` and `ahead` in one `_state_lock` take; the planned order let a test thread see `FULL` and move its fake clock first (3 tests failed with a 20 ms pause injected).
- B33 (pre-flight, critical): Couchbase decodes chunked bodies itself (`http.ChunkedBody`) instead of `HTTPResponse.read1()`, which waits inside a chunk boundary for the next size line: against a server holding between two 16 KiB flushes a step blocked for seconds, and Cancel, Discard, Load more and closing the tab waited behind it with nothing able to interrupt. Spec §3.4.2 was updated.
  - Cost: about 50 lines of framing code on every request; fuzzed at every split point, and every 04a Couchbase test passes plain, TLS and bastion.
- B35 (pre-flight): `READ_AHEAD_STEP_CHUNKS = 2`: a 16-read step took 0.42 s on 6-byte rows, the longest 2-read step 69–73 ms, and filling 8 MiB took the same 0.47 s. B32, B34, B36–B41 are mechanical and sit in the plan's table (B39: a server's error answer to ADVISE or a sample is not resent after a reconnect).
- Kept without a number: the `not_covered` text reads "the index lacks fields the query needs, as with SELECT *"; a LIMIT-bounded scan is not flagged sequential or primary; plan views cap at 10,000 operators, 200 levels and 100 findings (`unknown` beyond); `QueryFailed` is logged at INFO without its message and a 422 never echoes `input`; Explain and Run with profile are hidden on other engines; the 04a response parser was not touched (lean decoder → 04c).

## Carries

To 04c (the plan's table is [Carries to 04c](../plans/2026-10-19-04b-couchbase-query-workflow.md#carries-to-04c); the lines here add what execution found):
- Lean row decoder: one 20 MiB document peaks at 320–540 MB in 04a's `ResponseParser` (`fetch_raw(1)` alone shows it; sampling's second decode was sequential, CPU only, and Task 7 removed it). Keep nested values as text in `stream.ResponseParser._row` and give the collector a decode that does not build every object; the floor is about 4× the document.
  - Left out of 04b: it touches Tasks 2–3 code and 20 MiB documents are the edge; sampling is capped at 32 MiB, so at most two of them.
- A2 (`SELECT RAW $doc` equals what `SET d = $doc` stores) and A3 (non-object documents, the INSERT and remove forms) are still the first probes.
- The documents' read path can rely on whole-document text being exact (`SELECT d`, `SELECT RAW d` and `*` pass the stored text through); a projected field is re-encoded by the server (CLAUDE.md, known limits), so a save diff compares whole documents, never a projection.
- `services/metadata_errors.py` has `server_errors_are_final()`: every metadata-connection read that can fail with a server error goes through it, else `MetadataService` resends it after a reconnect (B39); writes use `with_connection(retry=False)` (D-04-9).
- The collection context menu (Browse documents / Details / Sample fields…, `Explorer.tsx`) is where 04c adds Open document by ID… and New document…; the grid's "Open document…" prefills from `effectiveContext` and `contextOfPath` (`features/query/queryContext.ts`). `Keyspace` (frozen, a cache key) is the documents API's keyspace model; `CouchbaseConnection.query(…, context=…)` and the internal-result helper of `sample_fields` serve `SqlppDocumentStore`; `FieldSampling` is the pattern for `DocumentCapable`.
- Dev seed: sampling's byte-cap test needs `u_big` to be the 9th of 12 `app.users` documents in key order, so 04c's tests must add documents somewhere other than `app.users`.

To later sub-projects or follow-ups:
- A TS test runner for the pure helpers (`params.ts`, `queryContext.ts`, `planModel.ts`, `unlockPrompts.ts`): Tasks 9–12b were checked with node scripts and the browser, and the scripts were scratch (Task 11's roughly 420 checks are gone), so the frontend rules have no committed test (B30).
- Stale parameter drafts are never pruned (a name that returns finds its value); at most 400 drafts persist and a draft over 1 MiB is not written. A selection run takes its parameters from the selection only.
- The 16 MiB stall reset was measured only on OrbStack, not over a VPN with small socket buffers; B42 keeps it conservative. 04b reads ahead for Couchbase only (B4): MySQL could free its connection the same way, and whether `net_write_timeout` (60 s) ends a long-paused MySQL result is unverified; PG and SQL Server drivers have no non-blocking read, and SQL Server's FreeTDS must not be entered for it (03b).
- Completion does not handle array elements (`a.items[0].`), UNNEST or LET aliases, or a `default:` prefix; a seen field with a dot in its name is not suggested (B22).
- Plan view polish: arrow keys between Plan and Grid, focus on recycled rows, and what Task 11 could not see (scrolling a long plan, a finding far down scrolling to its node, a narrow window).
- Community Edition paths (no profile, disabled Run with profile and advice, the sample without a primary index giving 4000) were tested with fakes only; the dev cluster is Enterprise.
- Parameter warnings are lost when the statement fails at the head: only the error shows.

## Deferred minor findings

- Read-ahead: two mutation survivors are unreachable today (TLS `pending()`, because 64 KiB reads exceed a record; `_unread`); a step can still wait for the rest of a TLS record already in flight; 8 MiB of held tiny rows is only about 1.1 MB of wire bytes, so the 16 MiB reset counts few bytes there and errs toward the early clean close; nothing unsticks a blocking step (B33 and B35 guarantee there is none); the INFO line at `DONE` has the request id and bytes, not rows held (DEBUG in the adapter); engines without read-ahead now read the clock at every pause.
- Parameters: named slots are not capped (positional ones are, ≤ 200); `NaN` and `Infinity` are refused before any warning; `1e999` shows the `number` badge until the run refuses it; a draft's text is in `workspace.json` (spec §3.11.2 only says History does not store it); the panel follows the document 150 ms after typing; `9223372036854775807.0` is flagged on purpose (the int64 it becomes depends on the platform).
- Explain and plan: a statement that starts with a comment before EXPLAIN gets a second EXPLAIN (B23); details are the server's expressions verbatim (lists as compact JSON, long `spans`); ADVISE under "No context" gives unqualified advice, and a lost connection resends it once (read-only; up to 80 s with a stalled node); a big profile is briefly decoded twice; `useQueryRunner` refetches History once after an Explain.
- Sampling: `cut_at_bytes` can be true when the crossing document was the last; row size counts characters (up to 3× the bytes for non-ASCII); no `USE INDEX` (Community gives 4000, shown raw); a sample that finishes after its profile was edited can re-cache the old settings; a visited detail tab keeps its sample when the LRU (100 keyspaces per profile) evicts it; the detail page samples at once while only the tree's entry opens the dialog; paths come in first-seen order.
- Context UI: picking the `default` row stores an explicit context, so the tab no longer follows a later change of the profile's default; the options refetch each time the menu opens (not hooked to Refresh schema); a default context that is neither in the schema nor current is not in the menu; History opens the 04a way (`database`) while profiles are not loaded; right-click on a collection selects nothing.
- Completion: a 158 KB statement takes about 300 ms in the inherited split and tokenize step (PostgreSQL too).
- UI: no fade at the tab strip's edges, so a hidden tab shows only by wheel, swipe or switching.
- Docs: the plan's "Rulings made during execution" stays empty (this note holds them) and its B3 row is superseded in place; the spec's §10 has no A22 (numbering follows the plan).
