## Outcome against the pain points (feature-priorities §2, §3, §8)

- §8 跨 DB 傳輸或複製資料 (the user's own request): delivered for tables, views, a schema's tables and a query tab's result, into any of the four relational engines (PostgreSQL, MySQL, SQL Server, SQLite, same engine included), in three modes (create a table, append, delete its rows then append). Every column's target type and what happens to its values on the way is in the preview before anything runs; the copy is one transaction per table and ends with one outcome per table. It opens from the tree (schema, Tables folder, table, view), the table tab's ⋯ ("Copy rows to…", with the filter), a result's "Copy result to a table…" and ⌘⇧P, and it is the third kind of job in Jobs. With 06a and 06b this covers the user's Navicat/DBeaver dump, execute-file and data-transfer use without an external binary (§8's "SQL dump" and "跨 DB 傳輸" are both done; the ER diagram is ⑦ and the MCP server ⑧, not started). Stepped on: one copy cannot replace a parent and a non-cascading child together on PostgreSQL or SQL Server (the preview says so, below).
- Q1 light and fast: no new dependency. JS main chunk 1,526.60 → 1,552.76 kB at Task 9 (gzip 492.29 → 499.10 kB), 1,553.60 / 499.37 after the wave; sidecar 49,552 → 48,192 KB (smaller, cause not found, below). A 2-chunk pipe sized by the rows' text keeps memory flat: the frozen sidecar copied 1,000,000 rows (about 230 bytes each, 6 columns) twice into each engine inside spec §7's budgets: PG → MySQL 19.3–19.9 s (budget 60), PG → SQL Server 87.9–90.1 s (150; 59–60% of it), PG → SQLite 12.8–12.9 s (60), SQLite → PG 19.9 s (60), sidecar RSS +3–22 MB (budget 40; peaks 93–108 MB). Startup did not move (cold 1.00–1.04 s, `footprint` 167–173 MB, backend 80–81 MB). The 06a/06b carry closed: PostgreSQL's Run SQL file after 06a F1 is +22–23 MB in the frozen sidecar (inside 30 MB; 62.7–63.1 s against 06a's 56.2–59.0), `MallocLargeCache=0` +12 MB. Stepped on, and said: the preview reads the catalog table by table (a 20-table append or replace into PostgreSQL sends 242 statements, about 12 a table; create 92, about 4.6; an estimate of 25–35 s for a 100-table append preview at 20–30 ms from the server), the PostgreSQL column query that the dump catalog shares is still slower than 06a's (below), a 500-table "Show all" was never measured, and SQL Server targets stay the slowest (100-row INSERTs, about 11,100–11,400 rows/s).
- Q2 never lose work: one transaction per table (MySQL's CREATE TABLE excepted, and said), one outcome per job (R-06-12), the plan taken once and never resent, the job outlives its dialog and a reload (06b's runner), a Cancel that arrives while a COMMIT cannot be cancelled is held and honoured before the next table, a source that never starts fails the pipe instead of hanging the copy, and a query tab's open transaction is never aborted by a copy (the copy never cancels a tab's read, pre-flight H2). Deleting the target or the source connection while a copy runs is refused (B13), and so is closing or switching the tab a copy reads. MySQL tables that cannot roll back are found by reading their engine, so "rolled back" is never said for rows that stand (Task 4's I-1). The wave made MySQL sessions strict (`STRICT_ALL_TABLES`): a value too long for a MyISAM column used to be cut with a warning from the second row of a multi-row INSERT (probed); it now fails the statement and the outcome says `unknown` with what was written. Stepped on: a MySQL table created by a failed copy stays (said, never auto-dropped); a cancelled copy leaves a query tab busy until its in-flight read returns; a reloaded job has no "Copy again…"; `setval` and identity seeds are not transactional.
- Q3 trustworthy (the project's reading: honest about what happened): every mapping and conversion is shown before the copy; a value the target cannot hold fails its row with table, row and column, never NULL, never cut; offsets go to UTC in Python keeping SQL Server's 7th digit; an INSERT's matched rows are checked (A16), so a trigger that skips rows rolls the table back; the 4×4 matrix reads every value back with mutation tests. Three silent changes were found and closed on the way: the matrix found that SQL Server reads a backslash before a line break inside a string literal as a line continuation and drops both (ruling S1: fixed in the one place that writes T-SQL literals, so ⑤'s grid edits, 06a's dump restore and 06c's copy all stopped changing such text); the final review found that a MySQL TIMESTAMP is copied as its UTC time (a +08:00 server shifts every value; now said in the preview, I-1) and that a replace into PostgreSQL or SQL Server of FK-linked tables always fails at the first parent with no warning (I-2, now warned). Known gaps, documented: a SQL Server INSTEAD OF trigger that skips rows (C14), a trigger that does `COMMIT; BEGIN TRAN`, MySQL's deadlock (1213) rule, a query's lossy grid reads (said per column).
- Q4 focus: three modes, no upsert, no sync, no resumable copy, no Couchbase (R-06-14, CR-1), no copy from a database node (C10: one schema at a time); a new table gets its columns, NOT NULL and its primary key only. The wave added no mode or feature.
- Q5 multi-engine: 16 engine pairs through one family table and one type map (`adapters/families.py`, `sql/type_map.py`; the engines' facts live there and in `transfer_sql.py`, the two references readers and the `columns.py` files); Couchbase is not offered as a source or a target.
- Q6 macOS: Return is the primary button and Esc closes (the job keeps running), ⌘⇧P entries, Zhuyin guards (`isImeKeyEvent` first on every key handler), the held-Return guard on Copy, reserved scrollbars under the mapping table and the statements, the ⌘Q question names a running copy. Checked in web mode by the coordinator only; nothing in the packaged app.
- §3 Must for ⑥: M3 (⌘⇧P "Copy data to…", the table tab's "Copy rows to…"), M7's value bar carried to copied values (big integers, NULL against empty, nothing changed silently), M9 ("Copy result to a table…" beside Export, in the status bar and the grid's menu), M11 (a red target makes Copy a danger button and the replace's DELETE red, a read-only target is greyed and refused with 403 before anything is sent, a query source may only read, copying a table into itself is refused). ## Company database checklist additions (06a's and 06b's lists stay)

### PostgreSQL
- Append into a table whose written columns include a numeric with a default, and one with a serial or identity: the `setval` after the copy only touches integer columns (before the fix, a numeric default failed every append with 42883). Only PostgreSQL 17 ran.
- Replace of FK-linked tables: the warning names the children that hold rows; PostgreSQL judges "holds rows" by storage size, so a child emptied but not vacuumed still warns, and a referencing table locked for 5 s makes the preview say "may fail … may hold rows". Confirm a busy table does not make the preview wait 5 s on every change. The wave's syntax (`AS MATERIALIZED`, `pg_partition_tree`, `condeferred`) exists from PostgreSQL 12; nothing older ran.
- A new table or column whose name is over 63 UTF-8 bytes (a CJK name hits it at 22 characters): the preview refuses with `name_too_long`.
- A table under row-level security as a source: the source session sets only `DateStyle` and `IntervalStyle`, not the dump's `row_security = off`, so the copy reads what the grid shows. Confirm which rows arrive.

### MySQL
- A server (or a profile with the `time_zone` option) that is not UTC, with TIMESTAMP columns: the preview's "MySQL TIMESTAMP is read as UTC" note, the copied values against the grid's, and MySQL TIMESTAMP into MySQL TIMESTAMP staying exact (no note).
- The login may `SET SESSION net_write_timeout` and `time_zone` (source) and `sql_mode`, `FOREIGN_KEY_CHECKS`, `time_zone` (target); the dev login may, and a login that may not was not tried.
- MyISAM (or any table that cannot roll back) as a target, and a server whose `default_storage_engine` is MyISAM: the engine read, 1196, and the strict session. A server with `lower_case_table_names` other than 0 (a created table the engine read does not find counts as non-transactional). Only MySQL 8.4 ran.

### SQL Server
- Replace of FK-linked tables (547): the warning reads `sys.partitions` for the children; whether a login without VIEW DEFINITION sees them in the catalog views at all (if not, no warning and the copy still fails honestly at 547); a memory-optimized child is read as empty, so no warning there.
- A login whose `user options` turn IMPLICIT_TRANSACTIONS on, as a copy target (the job session sends `SET IMPLICIT_TRANSACTIONS OFF`): never exercised against a real login (06a's L8 was fake-tested only).
- SQL Server → SQL Server create of a varchar, char or text column across two databases with different collations: the code-page note, and what arrives.
- `datetime2(7)`, `datetimeoffset(7)` and `time(7)` into PostgreSQL or MySQL (rounded by the server, noted) and out of a query (the driver drops the 7th digit, noted).
- A target table with an INSTEAD OF trigger that skips rows (not detected, C14) and one with a trigger that runs `COMMIT; BEGIN TRAN` (not detected).

### SQLite
- A target table whose key says `ON CONFLICT REPLACE` or `IGNORE`: the copy writes `INSERT OR ABORT`, so a conflict fails the table.

### Couchbase
